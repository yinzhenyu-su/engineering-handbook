# 成本-质量-延迟三角

一个语音助手只有大约 800 毫秒的时间开口回应，超过这个时长，对话就让人觉得断了。用户问它一个真正难的问题，那种推理模型能给出明显更好答案的问题。于是团队把难题路由给推理模型。评估集上的质量上去了。然后产品上线，每个难题都换来 28 秒的死寂，模型在吐出第一个字之前一直在思考。[^1]

团队得到的正是他们优化的东西。他们选了更高的质量，也拿到了。他们只是没注意到，自己正在拿产品一刻也离不开的那一项去换。

这种取舍就是本章的主题，而且它有形状。每一次调用托管模型，都会暴露三个可以度量的东西：花多少钱、答案有多好、用户等多久。你可以把其中任意两个推到极限。第三个会朝反方向走，除非你改变系统的结构。工程师把这叫做成本-质量-延迟三角（cost-quality-latency triangle），它也是本书后面反复回到的心智模型。

![一个三角形，三个顶点分别标注为顶部 High Quality、左下 Low Cost、右下 Low Latency；三角形内部有三块阴影区域，靠近底边的是 Realtime Chat，靠近左上边的是 High-Stakes Extraction，靠近右上边的是 Batch Summarization](../../../ai-eng/part-1-how-models-behave/images/05-triangle.png)
*你可以坐在三角形的一条边上，但不可能同时坐在三个角上；每个产品都停在它首要约束把它钉住的位置。*

## 三个维度都有真实的单位

只有每个角都是能放到监控面板上的数字，这个三角才有用。三个都能。

**成本**是每百万 token 的美元价，写作 `$/MTok`，分输入和输出。厂商把输入和输出分开计费，因为生成文本比读取文本更耗算力，所以输出价通常是输入价的 3 到 10 倍。整个市场的价差极大。截至 2026 年 6 月，Google 的 Gemini 3.1 Flash-Lite 输入 $0.25、输出 $1.50（每百万 token）。[^2] Anthropic 的旗舰 Claude Fable 5 是输入 $10、输出 $50。[^3] 光输入就是 40 倍差距，这还没算多轮上下文越堆越多。

**质量**是模型在你这个任务上的评估通过率：满足你定义的正确性门槛的响应占比。这里“你”字是关键。一个模型在某个任务上能拿 92%，换个任务可能只有 60%，所以质量从来不是烙在模型上的单一数字。它是模型与任务的配对，没法从排行榜上直接读出来。造出这个数字所需的评估集本身是一门功夫，Part 4（评估基础）会讲；眼下，先把质量当成你测出来的一个百分比，而不是一种感觉。

**延迟**分成两个对用户来说感受完全不同的指标：

- **首 token 时间（TTFT）：** 从发出请求到第一个分片流回来的毫秒数。这就是用户盯着空白光标的时间。
- **每秒 token 数（TPS）：** 文本开始输出后填充的速度。大约超过 200 TPS，聊天场景的读者反正也跟不上，瓶颈就成了渲染器而不是模型。[^4]

对任何交互式产品，TTFT 才是决定产品是否“活着”的数字。大多数团队从来没给它埋点。他们把“延迟”量成从发送到最后一个 token 的毫秒数，TTFT 就被埋进一个在图上看起来很健康的总数里。本章开头那个语音助手犯的正是这个错：总延迟几乎没动，因为推理发生在生成过程中，但 TTFT 从不到一秒炸到了 28 秒。[^1] [推理模型](./04-reasoning-models.md) 讲了那条隐藏的思维链为什么本来就会抬高 TTFT。

以下是 2026 年年中的延迟分布，正是这张图让推理陷阱变得触目惊心：

![一张第 50 百分位首 token 时间的横向条形图，条形从短到长排列：Cerebras 与 Groq 上的开源权重模型接近 0.2 秒，前沿标准模型在 0.7 到 1.1 秒之间，前沿最大推理模式则是 28 秒和 67 秒；2 秒处有一条竖直虚线，标注为 Interactive limit](../../../ai-eng/part-1-how-models-behave/images/05-ttft.png)
*推理模式不是一个更慢的设置项，它是另一个延迟量级；从标准前沿到最大推理的跳变是 30 到 60 倍，不是几个百分点。*

## 诚实地选两个

三角的压缩版说法是“选两个”。这是一句有用的谎言。下面是诚实的版本。

单一模型层级、固定任务、不用任何结构性技巧的前提下，无取舍的那个角并不存在。没有一个模型同时是最便宜、最快、在难题上又最好的。你只能坐在一条边上：

- **便宜又快：** 小模型。任何难题上质量都会掉。
- **便宜又高质量：** 大模型走 batch API，半价。你完全放弃交互式延迟，因为 batch 是异步跑的，最长 24 小时才返回。[^5]
- **快又高质量：** 大模型加优先推理。成本飙升。

这就是规则。接下来是它会弯的地方，因为假装它从不弯，正是团队被忽悠的方式。

**帕累托前沿每一代都在移动。**“选两个”描述的是某一时刻。模型每次发布都会同时改进三个维度。截至 2026 年 6 月，GPT-5.4 mini 输入每百万 token $0.75，能力相当于一年前的前沿价位。[^6] 2024 到 2026 年，前沿价格下降了约 80%。[^7] 这个三角是快照，不是物理定律。每隔几个月重新检查一次选型；你卡住的那条边可能已经挪了。

**你的流量不是单一任务。** 一天一千个请求的流里，难易混杂。典型聊天机器人流量里大约 80% 是简单的。只因为 20% 需要那份马力就把全部流量送去前沿模型，等于用小模型就能搞定的查询去付旗舰价。三角是按请求成立，不是按产品成立。[模型全景](./00-the-model-landscape.md) 讲了你在哪些层级之间做路由。

**质量没有全局排名。** 小模型可以在一个边界清晰的分类任务上做到 95%，在开放式写作上只有 40%。“你需要大模型来保质量”这句话，永远应该让你反问：在什么任务上的质量，怎么测的？没有针对任务的评估，这就是民间传说。

所以真正管用的规则比“选两个”更锋利。选模型之前，先说出你牺牲的是哪个维度，而且要说出声：

- 实时对话牺牲**成本**。你为一个能满足 TTFT 预算的能干模型付钱。
- 每晚跑的摘要流水线牺牲**延迟**。你拿 batch 折扣。
- 高风险抽取牺牲**成本**。你买的是不容出错的质量。

如果你说不出哪个维度可以牺牲，那你就没有模型问题。你有结构问题，而本章后半部分就是攻它的三条路。

## 三个产品，三个角

数字让三角变具体。三种真实的产品形态，映射到三个角上，用 2026 年 6 月的价格。

### 实时对话：延迟是硬墙

面向用户的聊天界面必须感觉即时。约束是 TTFT 在 2 秒以内，理想情况 1 秒以内。光这个预算就淘汰了所有推理模式（TTFT 28 到 67 秒），逼你用标准层级模型。[^1]

Claude Sonnet 4.6 输入 $3 / 输出 $15 每百万 token，TTFT P50 为 0.74 秒，合适。[^3] 跑在 Groq 或 Cerebras 上的开源权重模型在延迟上更合适，TTFT 接近 0.2 秒，前提是它的质量过得了你的评估线。[^4] 你**不该**做的是：查询看着难就去够推理层级，因为延迟悬崖在总延迟面板上看不见，在产品里却很残忍。

代价：成本。你全天跑一个中端模型而不是便宜模型，并且接受它。延迟动不了。

### 批量摘要：延迟可以白送

一条流水线每晚给 50,000 张工单做摘要。没有人在等。整个任务早上之前跑完就行。

这里延迟是便宜的维度，所以你就把它花掉。OpenAI 和 Anthropic 都提供 batch API，异步任务五折，最长 24 小时返回。[^5] 用 Claude Sonnet 4.6 给 50,000 张工单做摘要，假设每张 2,000 输入 token、300 输出 token，按标准价大约每 1,000 张输入 $0.50、输出 $1.35；batch 折扣再砍一半。你用小模型的成本买到了接近前沿的质量，纯粹因为你愿意等。

代价：延迟，而它对你毫无成本，因为没人在看。

### 高风险抽取：质量没有商量余地

一条流水线从法律合同里抽结构化字段：当事方名称、生效日期、责任上限。日期错了是真问题，不是错别字。量很小，一天几百份文件。

质量就是那堵墙。你选在你的抽取集上评估通过率最高的模型，哪怕那是 $10/$50 的旗舰，因为出错的代价远大于 API 账单。一天几百份文件，这点开销相对下游风险就是零头。

代价：成本。你故意每次调用都多付，因为另一条路是签好的合同里写错一个责任上限。

## 三种能部分绕过三角的杠杆

说出你牺牲什么，已经能走很远。但有三种结构性动作能让你弯一条边，而不是干脆把一个维度交出去。没有一个是免费的；每一个都用某个代价换来缓解。

### 提示词缓存：降成本，质量和延迟不变

当你每次请求都发同一段很长的前缀——系统提示词、工具定义、一大块检索到的上下文——你每次都要按全价输入为它付费。提示词缓存（prompt caching）拦住了这件事。厂商把稳定前缀处理后的形态存起来，复用只收你一小部分钱。在 Anthropic 上，缓存读取是基础输入价的 0.10 倍，也就是缓存那部分省 90%；一次性写入缓存是 1.25 倍。[^8]

输出与不走缓存逐字节相同，所以质量毫发无损，而且跳过 prefill 实际上还能降低长提示词的 TTFT。[^8] 这是少见的既不吃质量也不吃延迟的杠杆。它只打成本。

多轮上下文下这笔账会滚得很快。一个 10 轮的 agent，携带 50,000 token 的系统上下文，每轮 200 token 的用户消息和 500 token 的响应，跑在 Claude Sonnet 4.6 上：

```python
# Claude Sonnet 4.6 价格，2026 年 6 月：输入 $3.00 / 输出 $15.00 每 MTok
# 缓存写入为输入的 1.25 倍，缓存读取为输入的 0.10 倍

def without_cache(ctx, user, out, turns):
    inp = (ctx + user) * turns
    return inp * 3.00 / 1e6 + out * turns * 15.00 / 1e6

def with_cache(ctx, user, out, turns):
    # 第 1 轮写入缓存，后续轮次读取
    cost = ctx * 3.75 / 1e6 + user * 3.00 / 1e6 + out * 15.00 / 1e6
    for _ in range(turns - 1):
        cost += ctx * 0.30 / 1e6 + user * 3.00 / 1e6 + out * 15.00 / 1e6
    return cost

print(f"No cache:   ${without_cache(50_000, 200, 500, 10):.2f}")  # $1.58
print(f"With cache: ${with_cache(50_000, 200, 500, 10):.2f}")     # $0.40
```

同一段对话、同一个模型、同样的答案，成本砍掉 74.5%。[^8] 代价是架构上的纪律：被缓存的前缀必须在各次请求之间逐字节相同。缓存断点之前只要出现一个时间戳或每请求唯一的 ID，哈希就变了，缓存永远不命中。修法是一条布局规则：稳定内容放前面（系统提示词、工具、上下文），可变内容放最后（用户消息）。Part 2 的提示词缓存一节讲断点、各模型的最小 token 数，以及怎么确认命中了。

### 路由：把任务匹配到模型来降成本

如果 80% 的流量是简单的，把它全送去旗舰就是分类错误。路由能解决。网关按可能的难度给每个请求分类，送给在该难度下过得了质量线的最便宜的模型。标准做法是“先便宜后昂贵”：先试便宜模型，只有当某个轻量校验（schema 校验、置信度分数、一次快速二次评估）判定便宜答案不合格时，才升级到更强的模型。

升级会在便宜模型失手时多付一次调用的延迟。当升级率稳定在 20% 以下、层级间价差足够大（比如 5 到 10 倍）时，这笔买卖划算。

```python
from dataclasses import dataclass

@dataclass
class RoutingPolicy:
    ttft_budget_ms: int
    quality_threshold: float

def select_model(complexity: str, policy: RoutingPolicy) -> str:
    if complexity == "simple":
        if policy.ttft_budget_ms < 300:
            return "groq/llama-4-70b"   # TTFT P50 约 0.16 秒，2026 年 6 月
        return "claude-haiku-4-5"        # 每 MTok $1/$5
    if complexity == "medium":
        return "claude-sonnet-4-6"       # $3/$15，TTFT P50 约 0.74 秒
    # 困难：只有在延迟允许时才升到具备推理能力的层级
    if policy.ttft_budget_ms >= 10_000:
        return "claude-opus-4-8"         # 每 MTok $5/$25
    return "claude-sonnet-4-6"           # 对话预算内的最佳选择

chat = RoutingPolicy(ttft_budget_ms=2_000, quality_threshold=0.85)
assert select_model("hard", chat) == "claude-sonnet-4-6"  # 2 秒预算下 opus 太慢
```

注意难查询那个分支在 TTFT 预算紧张时拒绝升到推理层级。就是这一道守卫，语音助手团队漏掉了。把 TTFT 当成路由策略里的硬约束，而不是软目标，否则只要难题一来，推理模型就会悄悄把你的延迟预算打爆。[^1]

路由也不是免费的。它需要一个分类器、逐层级的评估验证，以及在线上流量样本上持续评估，因为你上线前建的评估集会和生产漂移。粗略的下限：每小时几百个请求以下，单模型就够了；流量上来且难度真的参差时，路由才开始划算。Part 2 的网关与路由一节讲实现；到了架构规模，网关本身（多厂商负载均衡、故障切换、成本监控）是个系统设计问题，HLD Part 9 会讲。

### 蒸馏：降成本降延迟，但要先付钱

蒸馏训练一个小号的学生模型，在一个很窄的任务上模仿大号的老师。你让老师生成一个很大的示范数据集，再拿它微调学生。一个蒸馏得好的模型，运行成本大约比它学的那款前沿模型便宜 130 倍、快 130 倍，但只限于它被训练的那个窄任务。[^7] 它学到的是条捷径，不是通用智能，任何偏离分布的东西它都会自信地胡说。

这是最贵的杠杆，也是唯一有真金白银前期投入的。从前沿老师训一个 7B 学生，光算力就要 5,000 到 30,000 美元，还不算人力。[^7] 划不划算就是一道除法：

```python
def breakeven_months(training_cost, teacher_monthly, student_monthly):
    savings = teacher_monthly - student_monthly
    return training_cost / savings if savings > 0 else None

# 高流量、自托管且硬件跑满：
print(breakeven_months(15_000, 14_000, 3_000))  # 1.4 个月 -> 值得做
# 中等规模，API 账单不高：
print(breakeven_months(15_000, 1_200, 1_000))   # 75 个月 -> 不值得
```

经验法则：回本在 6 个月以内是很强的候选，6 到 12 个月要想清楚，超过 12 个月几乎一定是选错了工具。[^7] 因为 2024 到 2026 年前沿价格降了约 80%，纯靠省 API 账单已经很少能证明蒸馏划算。2026 年还站得住的场景，是 API 出任何价都服务不了的：网络往返根本达不到的 100 毫秒以内延迟，以及医疗、金融或端侧那种物理隔离、隐私受限的部署。[^7]

陷阱是去蒸馏一个不稳定的任务。蒸馏模型在训练那一刻就冻住了。如果你的分类 schema 每季度改一次，每次改动就是又一轮 5,000 到 30,000 美元的再训练，成本优势立刻蒸发。只蒸馏窄、量大、稳定的东西。其余的都留在老师那边，改一句提示词不花钱。

> [!WARNING]
> **最常见的搞坏三角的方式，是只优化质量、从不给 TTFT 埋点。** 一条把难题升到推理层级的路由规则，在评估面板上和总延迟图上都像是纯赚，因为总时间几乎不动。同时 TTFT 跳了 30 到 60 倍，每个提问难题的用户都觉得产品卡死了。[^1] 在放任何推理模式变体进延迟敏感界面之前，先把 TTFT 当成独立指标，按模型、按路由跟踪。

本书里每一个产品决策都落在这个三角的某处。当一个选择让人为难时，动作永远一样：写下这三个数字，说出你负担得起牺牲哪个维度，再看缓存、路由或蒸馏能不能把那个你牺牲不起的买回来。
