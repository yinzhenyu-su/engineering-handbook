# 在线评估与 A/B 测试

一个团队拿 100 条样例的评估集跑了一次提示词改动。新提示词比旧的得分高 3 分。他们上线了。一周后，生产指标纹丝不动。两周后，客服工单略有上升。

模型本身没出问题。是评估在撒谎。每组 100 条样例、基线准确率在 80 多分时，80% 统计功效下你能可靠检出的最小准确率差异约为 10 到 13 分，而不是 3 分。[^1] 那 3 分的提升只是置信区间里的噪声，据此上线相当于把抛硬币包装成了一次测量。

离线评估能抓住明显的回归，[回归测试集与 CI 门禁](./04-regression-suites-and-ci-gates.md) 讲的就是这件事。但一个改动是否真的帮到了用户，必须由生产流量来裁决。本章讲的是生产环境能给你、而静态评估集给不了的两样东西：**隐式信号**（implicit signals）——每个真实用户一根手指都不用动就产生的信号，以及 **A/B 测试**（A/B test）——能把指标变化因果归因到你这次改动上的实验。这两样都比看起来更吵。整件事的胜负手就是样本量。

## 用户做什么，比用户说什么更诚实

点赞点踩组件是 AI 产品里最流行的评估工具，也是最差的工具之一。两个用户对同一条 Copilot 建议点了踩：一个因为变量名写错了，一个因为整条建议都不相关。两人产生的是同一个单比特信号。第三个用户把回答重新生成了四次然后放弃了，他根本没产生信号。

解法不是做一个五星评分组件，而是去衡量用户拿这条回答*做了*什么——这在每次交互里都是免费产生的。按各自指示质量的可靠程度排序，分三层：

**第一层是采纳。** 用户有没有一个字不改就复制走输出？有没有原样接受代码建议？有没有真的做成了他本来要做的事（提交代码、发布文档、解决工单）？这些信号最强，因为用户零成本：他把你给的输出当成了最终答案。一份从业者分析给出的数字是，有用的 AI 功能复制不改率在 25% 到 40%，低于 15% 就说明模型产出的东西形态本身就不对（截至 2026 年 4 月）。[^2] GitHub Copilot 把建议采纳率当作首要指标；一项 Zoominfo 的部署研究报告称，职业开发者中的建议采纳率为 33%、代码行采纳率为 20%（截至 2025 年 1 月）。[^3]

**第二层是诊断。** 重新生成率、编辑距离分布、超时放弃率。这些能告诉你某一类请求在失败，而且常常能告诉你*怎么*失败的。词级编辑说明内容对了、语气不对。整段删掉重写说明任务分布不匹配。坑在分群：技术类查询的重新生成率是 50% 到 60%，通用查询是 10% 到 15%。[^2] 把这两个人群混在一起取平均，两边都诊断不出来；更糟的是，流量结构一变，聚合信号就会翻转，而模型质量根本没动。

**第三层是参与度。** 用户 7 天内会回来吗？会话能聊到多深？这些是留存的领先指标。它们在单请求层面很吵，但聚合起来很稳；同一份分析认为，七天激活率是生产力软件里对三个月留存最强的预测因子。[^2]

*隐式信号的三个层级，按各自与实际质量的关联强度排序。显式的点赞点踩被放在一边，因为它跟参与度的相关性比跟质量更强。*

生产监控的默认配置是三层隐式信号全上，并按意图簇分群。显式点踩反馈只当作调查的*触发器*，不当主指标：一次点踩的意思是“去看这条链路追踪”。GrowthBook 引用的一项研究（2026 年 6 月）发现，点踩反馈跟整体参与度的相关性比跟质量更强。[^4] 如果你的看板按点赞率给功能排名，你排的其实是用户有多喜欢这个产品整体，那问的是错的问题。

## 对生产流量采样

隐式信号免费覆盖 100% 流量。任何比隐式信号*更重*的做法（对完整输出跑一遍 LLM 评委、把链路追踪送人工复核、跟参考答案算语义相似度）每个请求都要真花钱，你不可能在每次调用上都做。解法是采样。三种策略，各自回答一个不同的问题。

**按 1% 到 5% 的流量随机采样**给出总体质量的无偏估计。这是质量看板该用的默认值。风险在于稀有但严重的失败模式（那 0.1% 会编出药物剂量的查询）会被按频率等比例采到，而那基本等于永远采不到。

**分层采样**能解决这个问题。按意图给请求分簇（对查询做语义嵌入是常见手段），然后从历史错误率更高或业务风险更高的簇里用更高比例采样。总复核预算没变，但都集中到了失败真正发生的地方。

**按低置信度定向采样**用一个便宜信号来决定哪些请求值得做昂贵复核。评委模型的不确定性估计、两个模型之间的集成分歧，或者重新生成信号本身，都能标出最可能失败的请求。这正是 [LLM 评委（LLM-as-judge）](./01-llm-as-judge.md) 一鱼两吃的地方：给评估集打分的是同一个评委，它可以跑在一小片生产流量上，打低分的请求升级给人工复核。

```python
import hashlib
import random

def should_sample(request_id: str, base_rate: float,
                  intent_cluster: str, judge_score: float | None) -> bool:
    """Return True if this request should be deeply evaluated."""
    # 第 1 类：确定性的随机采样（对 request_id 做哈希以保证稳定）
    h = int(hashlib.sha256(request_id.encode()).hexdigest(), 16) / 2**256
    if h < base_rate:
        return True

    # 第 2 类：对高风险意图簇提高采样比例
    oversample = {"medical": 0.20, "legal": 0.10, "billing": 0.05}
    if h < oversample.get(intent_cluster, 0):
        return True

    # 第 3 类：针对评委低置信度的请求
    if judge_score is not None and judge_score < 0.4:
        return random.random() < 0.5
    return False
```

对 `request_id` 做哈希、而不是每次现掷一个随机数，意味着同一个请求在重放时会得到同样的采样决定。你在调试评估流水线、需要确定性行为的时候，这件事很关键。

还有一种策略值得单独给个名字：**影子模式**（shadow mode）。在任何难以回滚的模型或提示词改动上线之前（换微调模型、大改提示词），把真实生产请求同时路由给当前版本和候选版本，只把当前版本返回给用户，离线比较候选版本的输出。影子模式让你在用户零风险的前提下拿到真实的生产分布。代价是这段时间的推理开销大约翻倍。在把候选版本暴露给用户之前，先拿 5% 到 20% 的流量跑一两天。

一个警告，因为 Intercom 为这一条付过昂贵学费：影子模式的比较用的是离线指标（语义相似度、评委分数），而离线分数更高不等于业务结果更好。Intercom 的 Pedro Tabacof 记录过一个案例：某个提示词变体的离线评估分数*更低*，A/B 测试的业务结果却更好。[^4] 影子模式能抓住明显的分布失效。上不上线的决定仍然属于线上 A/B 测试。

## 为什么 LLM 的 A/B 测试需要更大的 N

经典 A/B 测试假设两件事，这两件事对改按钮颜色成立，对改 LLM 不成立：[^5]

1. 每个用户的方差相对你要检出的效应很小。
2. 每次测量大致是从一个稳定的用户行为分布里独立抽样。

LLM 功能把这两条都炸了。**用户间方差更高**，因为输入是自然语言：两个用户问“同一个”问题，措辞不同，就把模型送进了输出分布的不同区域，产出的答案在延迟、长度和下游行为上都不同。**用户内方差也高**，高到确定性功能完全没有对应物：同一个用户在两段会话里问同一个问题，可能得到实质不同的答案，原因包括温度参数、检索新鲜度和并行 GPU 执行中的浮点非确定性。有研究记录到，相同的模型权重跑在两家云厂商上，性能差异在统计上显著（p=0.013）。[^5]

实际后果是：一个 LLM 功能的方差是确定性功能的 2 到 5 倍。[^5] 拿你上次按钮实验的历史方差去喂标准样本量计算器，算出来的数字会正好差这个倍数。要想到达同样的统计功效，你需要 2 到 5 倍的样本量，或者 2 到 5 倍的实验时长。

每个团队在开实验之前都该跑一遍这个数字：

```python
import math
from scipy.stats import norm

def ab_sample_size(p_baseline: float, p_treatment: float,
                   alpha: float = 0.05, power: float = 0.80) -> int:
    """Required N per arm for a two-proportion z-test."""
    z_alpha = norm.ppf(1 - alpha / 2)
    z_beta = norm.ppf(power)
    var1 = p_baseline * (1 - p_baseline)
    var2 = p_treatment * (1 - p_treatment)
    delta = abs(p_treatment - p_baseline)
    return math.ceil(((z_alpha + z_beta) ** 2 * (var1 + var2)) / (delta ** 2))

for lift in [0.10, 0.05, 0.03, 0.02]:
    print(f"Lift={lift:.0%}: N per arm = {ab_sample_size(0.82, 0.82 + lift)}")
```

从 82% 的基线跑一遍，输出令人清醒：

| 你想检出的效应 | 每组 N |
|---|---:|
| 10 个百分点 | 210 |
| 5 个百分点 | 870 |
| 3 个百分点 | 2,400 |
| 2 个百分点 | 5,400 |

要在 5% 显著性、80% 功效下可靠检出 3 分的提升（82% 到 85%），每组大约需要 **2,400 条样例**。[^1][^8] 而公司内部评估集的平均水平是 50 到 200 条人工挑选的样例。100 条样例时，你能检出的最小提升是 10 到 13 分，不是 3 分。比这更小的差异，是测试在告诉你它不知道。

这个关系是二次的：标准误按 N 的平方根收缩，所以你想检出的效应量减半，需要的样本量就*翻四倍*。

LLM 的随机性让这件事更糟。同一个模型在同一个评估集上跑两次，分数就会动。Lumiste 2023 年在 64 条样例的集合上做的演示显示，GPT-4 的准确率在连续多次完全相同的运行之间从 65% 弹到 75%。[^6] 如果跑两次测试本身就有 10 分的抖动，那么 73% 的基线和 76% 的实验组之间就不是一个结果，而是一次抛硬币——你只是抛了两次。

> [!WARNING]
> **当 p 值掉到 0.05 以下就提前停掉 A/B 测试，会抬高假阳性率。** 在一个固定时长的实验里去看 20 次看板，名义 alpha=5% 也会把真实假阳性率推到 40% 左右。[^7] 如果必须偷看，用序贯检验（alpha 消耗法或 always-valid 推断）；如果不用，就事先定好 N 然后跑完。停止规则要在实验开始前预注册。

对 LLM A/B 测试最有用的降方差手段是**配对分析**（paired analysis）。当两组评估的是相同的问题或相同的用户时，去算逐问题或逐用户的差值，而不是比较合并后各组的均值。两组之间的协方差（由问题难度或用户异质性驱动）会相互抵消，剩下的残差方差才是你的改动真正推动的部分。Anthropic 的统计评估工作记录到，前沿模型在热门基准上的逐题得分相关性在 0.3 到 0.7 之间；在相关性 0.5 的情况下做配对分析，所需 N 大约减半。[^8] 把 3 分检出场景做成配对版本，每组从 2,400 降到约 1,200。

对已有存量用户的实验，**CUPED**（Controlled-experiment Using Pre-Experiment Data，用实验前数据做控制的实验）值得了解：用每个用户在实验前同一指标上的行为，把他结果里可预测的那部分回归掉，残差方差就按 1 减去相关系数平方的比例收缩。实验前后行为相关性为 0.7 时（参与度类指标的常见值），CUPED 能把方差降低约 51%，等于不花额外成本把样本量翻倍。[^9] CUPED 在两种情况下不再有用：你的用户大多是新人（没有实验前数据），或者改动大到实验前行为已经无法预测实验后行为。

## 把它们串起来的流水线

从这一切里浮现出来的纪律是一个三级漏斗，而不是一个单点决策。离线评估过滤掉明显的失败。影子模式暴露离线集没有预料到的生产分布问题。样本量足够的线上 A/B 对着业务指标做上不上线的裁决。每一级抓的是不同类别的问题，跳过任何一级，要么上线一个回归，要么把流量浪费在那些 30 行评估就能免费毙掉的改动上。

Intercom 那个案例是最清楚的说明：离线分数*更差*的提示词赢了 A/B 测试，团队的结论是他们“现在对中间评估的依赖少了很多，让生产数据来做决定”。[^4] 这不等于离线评估没价值；它的意思是离线评估是过滤器，不是判决书。用它低成本地毙掉明显的输家，用 A/B 测试来挑赢家。

规划 A/B 测试时要记住的数字是：80% 功效下检出 3 分提升，每组 2,400 条。如果你的流量在合理的实验窗口内撑不到这个量，你有三个诚实的选择：把目标效应量调大（并接受小胜将不可见），用配对分析或 CUPED 压低所需 N，或者带着明确的置信区间报告离线结果、别再假装评估能回答一个它分辨率不够的问题。陷阱是第四个选项：拿功效不足的结果上线，然后在生产环境里发现你本该在计算器上就承认的事。

隐式信号是让你在实验结束后还能继续评估的那一层。改动上线之后，复制不改率、分群后的重新生成率、7 天回访率，就是你能察觉“这个胜利站住了”“这个胜利褪色了”还是“这个胜利只是首批用户的新鲜感”的方式。它们不花额外成本，覆盖 100% 流量，而且比任何评分组件都更难被骗。工作量在于一次性的埋点，以及此后永远小心地分群。
